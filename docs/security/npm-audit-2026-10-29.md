## Pourquoi `--omit=dev` remonte quand même des outils de développement

`better-auth` déclare `prisma` et `vitest` comme dépendances de pair optionnelles. Comme
notre `package.json` les a en `devDependencies`, npm les rattache à `better-auth` et ils
restent dans l'arbre « production » de l'audit, avec tout ce qu'ils tirent
(`@prisma/composer-cli`, `alchemy`, `@prisma/dev`, `hono`, `lodash`, `tinypool`…).
Ce sont des outils de ligne de commande ou de test, jamais exécutés par l'application.

Vérification faite sur le build de production (`rm -rf .next && npm run build`) :
`hono` (seules les occurrences de « honor » dans Next), `chevrotain`, `alchemy`,
`tinypool`, `tar`, `valibot`, `html-to-text` et `@react-email` sont **absents** de
`.next/server` et `.next/static`. Les traces `nft` (paquets externes chargés à
l'exécution) ne contiennent que `next`, `react`, `pg`, `sharp` et leurs dépendances.

## Ce que l'application utilise réellement de Neon Auth

`src/lib/auth/server.ts` appelle `createNeonAuth` ; le code n'utilise que
`signUp.email`, `signIn.email`, `signOut`, `deleteUser` et `getSession`. Le serveur
`better-auth` lui-même tourne chez Neon (`NEON_AUTH_BASE_URL`), pas dans notre
déploiement : le bundle ne contient que le client (table de chemins d'API). Aucun
fournisseur OAuth, lien magique ni composant `auth-ui` n'est utilisé.

## À décider (non appliqué)

1. **Vitest 3 → 5** (corrige `vitest`, `tinypool`, `@vitest/mocker`, soit 1 critique + 1 critique + 1 modérée,
   mais uniquement dans l'outil de test) :
   `npm install -D vitest@5.0.5`
   Montée majeure : demande de relancer toute la suite (63 tests, dont l'intégration sur la branche Neon) et de
   vérifier `vitest.config.ts`. Pas de bénéfice pour la production.
2. **Forcer `better-auth` et `zod` plus récents sous Neon Auth** (corrige `better-auth` critique, `drizzle-adapter`,
   `zod`) : ajouter à `package.json`
   `"overrides": { "better-auth": "1.7.14", "@better-auth/core": "1.7.14", "@better-auth/oauth-provider": "1.7.14", "zod": "4.6.7" }`
   puis `npm install`. Non testé : `@neondatabase/auth@0.7.0-beta` épingle `better-auth` à 1.7.6 exactement et les
   mêmes versions pour ses paquets `@better-auth/*` ; mélanger des versions sur une bêta risque de casser la
   connexion. À ne faire que si un des avis devient atteignable (par exemple si on ajoute OAuth ou les liens magiques)
   ou quand Neon publie une version qui épingle `better-auth` >= 1.7.7 (`npm view @neondatabase/auth versions`).
3. **Prisma** : aucune action. Les correctifs viendront de nouvelles versions rc de Prisma 8
   (`npm view prisma versions`). Ne pas suivre la suggestion de npm (`prisma@7.10.1`).

## Comment relancer

```sh
npm audit --omit=dev                 # état courant
npm audit fix --omit=dev --dry-run   # ce qu'un correctif sans --force changerait
npm audit fix                        # applique (jamais --force)
npm ci                               # restaure toutes les dépendances si besoin
rm -rf .next && npm run build        # le cache .next périmé fait échouer le build après un changement de dépendances
```

À refaire après chaque montée de `@neondatabase/auth` ou de Prisma, puis réévaluer
les lignes « À décider ».
